# Commit Changes

Create commits with clear, conventional messages that explain WHAT changed, WHY it matters, and HOW it achieves the goal.

## Pre-Commit Verification (REQUIRED)

Before every commit, verify you're committing to the right place:

1. **Branch check**
   ```bash
   git branch --show-current
   ```
   Ask yourself: "Is this the right branch for this change?"

2. **PR scope check** (if a PR/MR exists for this branch)
   ```bash
   gh pr view --json title,baseRefName 2>/dev/null || echo "No PR"
   ```
   (GitHub shown; on GitLab use `glab mr view`; on an unrecognized forge check via its UI/API.)
   Verify: Does this change match the PR's stated scope? Is the base the repository's default branch?

3. **File ownership check**
   ```bash
   git diff --name-only --cached  # or git diff --name-only if nothing staged
   ```
   If a plan exists with a file allowlist, verify all changed files are allowed.

**If ANY check fails: STOP and ask user before proceeding.**

## Workflow

1. **Verify context** — Run pre-commit verification above
2. **Gather changes** — Run `git status` and `git diff --staged` (or `git diff` if nothing staged)
3. **Understand intent** — What problem does this solve? Why now?
4. **Craft the message** — Follow structure below
5. **Commit** — Use `git commit -m "subject" -m "body"` or multi-line format

## Message Structure

```
<type>(<scope>): <subject>

<body>
```

**Subject line** (required):
- Type: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `style`, `perf`, `ci`, `build`
- Scope: affected area (optional but helpful) — e.g., `auth`, `api`, `ui`
- Subject: imperative mood, lowercase, no period, ≤50 chars

**Body** (required for non-trivial changes):
- **What**: What is this change addressing?
- **Why**: Why does this matter now?
- **How**: Intent of the approach (not implementation details)

**Breaking changes**: Add ! after type/scope and explain in body:
```
feat(api)!: change authentication flow

BREAKING CHANGE: JWT tokens now required for all endpoints.
```

## Guidelines

- One logical change per commit — split unrelated changes
- If explaining "and" in the subject, consider splitting
- Staged changes only — don't commit untracked files without asking
- Review diff before committing to catch unintended changes
- Never add "generated by Claude", "co-authored by Claude", or any AI attribution to commits
